# XML Parsing Mechanics — mandatory for every agent, before its first parse

Every agent extracts by reading XML directly — these rules are mandatory, not advisory. The
vocabulary below is **evidence-anchored** (verified against live rules and the HRLifeImp /
ODPipeline fixture corpus, most recently 2026-07-16) but **not exhaustive**: when a tag isn't
listed here, read the XML and derive its meaning in context; never invent tag names in findings —
quote the actual tag and value you read.

## Envelope and retrieval

- `pega_get_rule_xml` returns a JSON envelope — the XML is in `rule_info`. If a fetch fails with
  the environment set, retry with the environment param omitted.
- Rule identity is `(class_name, rule_name)`, never bare name. Property and rule names are
  **case-insensitive** (`.Status` == `.status`) — match and group case-folded.
- The graph `REFERENCES` count is an upper bound in both directions: it over-counts (unrelated
  same-named rules from distant classes, condition-only refs, system props) and under-counts
  (confirmed to miss real field bindings). The XML is the source of truth for what's actually
  bound.

## Section feasibility gate (before extracting anything)

- **Auto-gen gate**: section-level `pyAutoHTML=true` **and** empty `pyJavaStream` **and** no
  non-empty `pyLegacyControl` anywhere. Do not gate on `pzIsAutoGenerated` — verified `false`
  even on genuinely auto-generated sections.
- A non-auto-generated section's cells cannot be reliably enumerated — flag the whole section
  (pattern E15) and analyze it by reading, not by cell-walking.

## Field bindings

- **Field binding** = a `rowdata` with `<pyType>FIELD</pyType>` whose **direct-child** `<pyValue>`
  starts with `.`. The direct-child `pyValue` is a sibling of
  `<pxObjClass>Embed-Display-Table-Cell</pxObjClass>` (an "anchored" binding). Param/source
  `pyValue`s nested inside `pyDataPageParams`/`pyDataPage`/`pyReportDefinitionPage` are NOT field
  bindings.
- A FIELD cell with no direct-child binding but a descendant `.`-prefixed `pyValue` is atypical:
  take the descendant as a fallback but flag it (`NON_ANCHORED_BINDING`) — confirm it is not a
  parameter or source value.
- Exclude `.pyTemplate*` bindings (design-time control-template placeholders for
  pxButton/pxChart/etc.) and `px*`/`pz*` system-plumbing properties — list them as exclusions,
  don't silently drop them.
- **Control**: `pyFormat` on the cell; fall back to `pyControl`. Required flag `pyRequired`;
  label `pyLabelFieldValue`.
- Multi-segment paths (`.CandidateData.ProposedLocation.City`) bind through an embedded page —
  the leaf's context is the embedded page path, not the section's class.

## Conditions on cells and containers

- Tags: `pyVisibleWhen` (or `pyWhen`), `pyRequiredWhen`, `pyReadOnlyWhen`, `pyDisabledWhen`,
  `pyExpression`, `pyCondition`; action-level conditions in `pyActionConditions` (a PageList —
  read it whenever non-empty).
- A condition value may be a When rule name, a negated name (`!IsClinicianInfoSelectedExisting_CO`
  — strip `!` to resolve the rule, record the negation), or an inline expression.
- **Conditional required-ness encoding** (verified): `pyRequired=true` together with a non-empty
  `pyRequiredWhen` (and marker `pyRequiredNew=truewhn`) means "required when condition" — this is
  the normal encoding, NOT an inconsistency. Only flag a genuine conflict (e.g. required
  hard-true in one cell and condition-based in another cell of the same property).

## Sub-section includes

- Every `<pyInclude>` anywhere in the stream (static SUB_SECTION includes AND section-body-level
  includes whose cell carries no `pyType`).
- SECTION / SUB_SECTION cells: direct-child `<pyValue>` plus legacy name tags `pySectionName`,
  `pyReference`, `pySubSectionName`. This covers grid-chrome includes (`pyGridPaginator`,
  `pzPegaDefaultGridIcons`) and **dynamic property-driven includes** (a `pyValue` like
  `.ContractInfoSetion_Name` — the included section is resolved at runtime from a property; flag
  it, and resolve candidate values from the property's source if possible).

## List sources on cells

Cell source lives in `pyListDataSource` blocks (a cell can carry more than one — a concrete
named source wins over `associated`/empty; a stray `pyListSource=associated` on a
**non-list** control is template noise, not a real source):

- `pyListSource` / `pyListDataSource` kind tokens: `datapage`, `reportdefinition`, `clipboard`/
  `page`, `associated` (property-level), `activity`, `local`/`prompt`/`valuelist`/`constant`.
- **datapage**: `pyDataPage` block (`pxObjClass Embed-Control-Mode-ListDefinition-DataPage`) —
  `pySourceName` (the D_ page), `pyValue` (value property), `pyPrompt` (display property),
  `pyPromptClass` (result class), `pyHasDPParam`, `pyUseParameterForSearch`, params in
  `pyDataPageParams`.
- **reportdefinition**: `pyReportDefinitionPage` — `pySourceName` or `pyReportDefinitionName`,
  `pyPrompt`, `pyValue`, `pySmartPromptClass`, params in `pyReportDefParams`.
- **clipboard**: `pyCBPage` — `pyPageName` or `pySourceName`, `pyValue`, `pyPrompt`.
- **Params** (both containers): each `rowdata` has name in `pyName`|`pyWord`|`pyParamName` and
  value in `pyValue`|`pyReference`|`pyParamValue`; the param is **by reference** when
  `pyReference` is set or the value starts with `.` — a by-reference param is a real property
  dependency (and a pattern-#8 review candidate).

## Autocomplete / selection mappings (verified vs `ClinicianInformation_Existing`)

Inside the `pyDataPage` block of an autocomplete-style control:

- `pyAdditionalFields` PageList (`pxObjClass Embed-AdditionalFields`), one `rowdata` per column:
  - `pyDisplayProperty` — the source column from the result row (may be `.pyID`, `.pxObjClass`,
    `.pzInsKey`).
  - `pyUseForSearch` — column participates in search matching.
  - `pyShow` — column visible in the results list (`false` + `pySetValueOnSelect=true` = a
    **hidden copy** — pattern E14/E18 evidence).
  - `pySetValueOnSelect` — on selection, the column value is copied.
  - `pyPropertyTarget` — where it is copied: `Associated property` (the control's own bound
    property) or an explicit path (e.g. `.ProviderData.ClinicianInfo.ProviderName`). **Every
    explicit target is an implicit property dependency** the graph may not show.
  - `pyIsPrimaryRow` — the primary (bound) column.
- Control-mode flags worth reading: `pyAllowFreeFormInput` (free text allowed on a lookup —
  E18 risk), `pyDisplayAsComboBox`, `pyLightWeightAutoComplete`, `pyMaxRecords`-style limits,
  grouping tags (`pyEnableGrouping`, `pyGroupLabel`).

## Action sets and events (verified vs `ClinicianInformation_Existing`)

Action sets live in a **`pyActionSets`** PageList inside the control's cell block (at the
`Embed-Control-Mode-ActionSets` level, NOT the sibling `pyBehaviors` field which has never been
observed populated — corrected 2026-07-17 per Pattern 10 investigation). Each `rowdata`
(`pxObjClass Embed-Control-Mode-Behaviors`) is one event–action pair:

- `pyEvent` — observed: `change`, `keyboard`, `click`; treat unlisted values as discoverable.
- `pyKeyCode` — non-empty (e.g. `down`) means a keyboard-specific trigger → pattern E17.
- `pyAction` — observed: `postValue`, `refresh`, `RunActivity`; treat unlisted values
  (setValue, localAction, runScript, openAssignment, …) as discoverable and record verbatim.
- `pyActionLabel` (display name), `pyUIElement`, `pyActionConditions` (PageList — conditions
  gating the action; resolve any named When).
- `pyActionAPI` — the wiring block:
  - `pyTarget` — `thisSection` | `otherSection`.
  - `pySection` — the refresh-target section name when `pyTarget=otherSection` (an **implicit
    section dependency**; add to the tree).
  - `pyActivity` + `pyActivityParams` — activity invocation (**empty `pyActivity` = no
    activity**).
  - `pyPreDataTransform` → `Embed-Invoke-DataTransform` with `pyName` +
    `pyDataTransformParams` — a refresh-time data transform (**empty `pyName` = no transform**;
    non-empty → pattern E13).
  - `pyDisableSubmit`, `pyActivityClass`/`pyActivityClassOrig` (context class).
- Multiple `rowdata` entries on one control form an **action chain in index order**; the same
  chain repeated under a second event (e.g. `change` and `keyboard/down`) is a duplicated
  trigger — list each trigger, analyze the chain once.

## Property rules (Step 4 vocabulary)

- `pyPropertyMode` (mode; `PageGroup`/`ValueGroup` → Step 8d), `pyPropertyModeLabel`,
  `pyStringType`, `pyStreamName` (default control).
- Property-level source ("Table Type"): `pyTableOption` (modern) or `pyTableType` (legacy) —
  tokens map: `locallist`/`promptlist` → local list; `datapage`/`datatable`/`classkeyvalue` →
  data page; `reportdefinition` → report definition. DP name in `pyTableClass` |
  `pyPromptTable` | `pySourceName`. Local list values in repeated `pyStandardValue`.
- A property-level source is the key Constellation-readiness signal (pattern #4): the field can
  be reused as-is regardless of cell-level overrides.

## Report definitions (Step 8b vocabulary)

- Applies-to class `pyClassName`; joins in `pyJoinClass` (each non-empty value = a joined
  class); a real sub-report only when `pySubReportName` is non-empty (empty placeholder elements
  don't count); index access when `pyUseIndex=true` or the applies-to class contains `-Index-`.

## Flow Action rules (Phase 0 vocabulary)

- UI sourcing: `pySectionReference` | `pyViewReference` | inline Design Template body
  (`pySections[].pySectionBody[].pyInclude`). Check all three.
- Wired logic: `pyValidateActivity`, `pyActionTransformRule`, pre/post processing activity and
  local-action configuration — each non-empty value is a root-level tree node.
